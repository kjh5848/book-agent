# 이미지 및 에셋 가이드라인 (3대 원칙)

본문(Chapter)을 집필할 때 보조 자료(다이어그램 및 캡처)는 다음 3대 규정 안에서만 삽입 가능합니다.

### 원칙 A (흐름/아키텍처 다이어그램)
- 위치: 각 챕터 초반부 `## 1. 개념 설명` 파트 직후뿐만 아니라, **실습 중간중간 새로운 모듈이나 아키텍처가 추가되어 이해가 필요한 모든 곳**에 유연하게 배치 가능합니다.
- 포맷: 텍스트 다이어그램 (Mermaid)
- 목적: 해당 구간에서 구현할 시스템의 완성된 데이터 흐름이나 아키텍처의 전/후 구조를 명확히 보여줍니다.

### 원칙 B (개념 이해 보조: 시각적 비유 프롬프트 선동일 주입)
- 위치: 초보자가 단번에 이해하기 어려운 추상적 개념, 복잡한 로직, 혹은 단계적 변화를 긴 줄글로 설명해야 하는 모든 분기점.
- 포맷: 마크다운 주석 형태의 **제미나이(Gemini) 이미지 생성 프롬프트** (실제 이미지를 삽입하지 않습니다).
  - 예시: `<!-- [Gemini 이미지 프롬프트]: "벡터 DB에서 유사도를 찾는 과정을 거대한 도서관에서 사서가 돋보기로 책을 스캔하는 직관적인 비유로 그려줘. 초보자가 이해하기 쉽도록 단계별로 표현할 것" -->`
- 목적: 에이전트가 글씨만으로 묘사하기 힘든 부분(예: RAG 파이프라인 흐름, 데이터 구조 등)을 시각적인 자료와 비유를 통해 독자가 직관적으로 이해할 수 있도록 돕습니다.
- **[핵심 작성 시기]**: 글을 모두 다 집필하고 몰아서 프롬프트를 넣으려 하지 마십시오. **본문 챕터를 집필하는 그 순간(마크다운 작성 중)**에 문맥 흐름에 몰입하여, 이미지가 있으면 좋겠다고 판단되는 곳에 실시간으로 프롬프트를 짜넣고 글을 이어가세요. 실제 그림은 작업자가 추후 일괄 생성합니다.

### 원칙 C (실습 완성 결과물 실제 캡처 적용)
- 위치: 실습 코딩 스니펫을 설명 완료한 직후, 실제로 시스템이 구동되는 화면 부분
- 포맷: 외부 이미지 파일 (예: `![정상구동회면](../../assets/CH02_result_success.png)`)
- 목적: **[중요] 에러가 발생하는 의도된 학습 과정을 제외하고는, 오직 "최종적으로 코드가 완벽히 동작하는 성공 출력 결과"만 캡처하여 삽입하십시오.**
- 수행 방법: 캡처 위치와 내용은 예제 코드의 `README.md`에 명시된 가이드라인 (`<!-- [캡쳐 사진 삽입 위치: ...] -->`)을 그대로 따릅니다. 캡처를 일괄적으로 뜰 수 있도록, 터미널 세션을 분리하거나 터미널 로그 전문이 출력된 화면을 촬영하세요.

### [에셋 저장 파일 규칙]
안티그래비티는 코드를 구동, 검증하고 결과를 캡처할 때 **반드시 에셋 폴더 아래에 평탄화(Flat)하여 저장**해야 합니다.
- **저장 위치**: `[프로젝트_출력_루트]/assets/` (예: `anti_v2_book/assets/`) 폴더 바로 아래 (챕터 하위폴더 허용 안함)
- **네이밍 컨벤션**: `[장번호]_[타입]_[상세].png` 형태.
  - 예시: `CH01_concept_rag.png`, `CH02_result_cli.png`
- **마크다운 링크 규격**: `![이미지 캡션 내용](../../assets/CH01_concept_rag.png)`
- **시인성**: 브라우저 전체 창 캡처를 지양하고, 결과가 잘 보이도록(주소창 자제) 필요한 부분만 크롭해서 보여줍니다.
