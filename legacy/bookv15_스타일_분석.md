## 1. 전체 구조 및 서사 설계

### 1.1 스토리 프레임워크: "캐릭터 성장 서사"

전체 글이 **"메타코딩"** 이라는 가상 주인공의 **성장 이야기** 로 관통됩니다.

| 요소 | 설명 |
|------|------|
| **주인공** | 메타코딩 — AI를 처음 배우는 개발자 |
| **목표** | 팀장에게 부여받은 "자율주행 청소 로봇 AI 개발" |
| **멘토** | 김선배 — 경험 많은 시니어 개발자 |
| **서사 구조** | 실패 → 원인 분석 → 해결 → 다음 도전 (반복) |
| **시간축** | 1주차 → 2주차 → ... → 5주차 (에피소드 형식) |

### 1.2 챕터 구성: 버전 업그레이드 패턴

기술 개념을 **시뮬레이터 버전(v0 → v1 → v2 → ... → v6)** 으로 대응시킵니다.

```
프롤로그 ─ AI 전체 조감도 (회귀, 분류, 강화학습, 딥러닝)
0화: v0 — if문 규칙 기반 (AI 이전 단계)
1화: v1 — DQN으로 첫 학습 (강화학습 + 신경망)
2화: v2 — 과적합 해결 (경사하강법, 역전파)  
3화: v3 — 데이터 분리 (훈련셋/테스트셋, 경험 리플레이)
4화: v4 — 학습률 최적화 (LR Scheduling, Adam)
5화: v5 — 추론 최적화 (캐싱, Policy)
번외: v6 — 다른 AI 기법 (의사결정 트리, RNN, 트랜스포머)
에필로그 ─ 용어 사전 + 이해도 체크리스트
```

> [!IMPORTANT]
> 핵심 원칙: **한 화 = 하나의 기술 개념 = 하나의 버전 업그레이드 = 하나의 실패와 해결**

## 2. 문체 및 톤

### 2.1 경어 체계: 해요체 (반말 혼용)

기존 KI의 '하십시오체'와 **다르게**, 이 책은 **해요체 + 구어체 반말** 을 자유롭게 혼용합니다.

```
✅ 사용 패턴:
- "~입니다 / ~합니다" (설명 문장)
- "~거죠" / "~겁니다" (구어체 연결)
- "~해요" / "~봐요" (친근한 요청)
- "~잖아요" (공감 유도)
- 직접 반말 혼용: "마치 식당 세 군데만 가보고 '여기가 최고!'라며"
```

### 2.2 화자(話者) 구조: 다중 목소리

| 화자 | 역할 | 표현 방식 |
|------|------|----------|
| **서술자** (저자) | 개념 설명, 비유 제시 | 해요체/합니다체 |
| **메타코딩** | 감정 표현, 실수, 깨달음 | 큰따옴표 직접 인용 `"와! 진짜 된다!"` |
| **팀장** | 문제 제기, 다음 도전 유도 | 대화체 `"이 맵 이외에서도 잘 되나요?"` |
| **김선배** | 핵심 개념 전달 | 멘토링 대화체 |

### 2.3 핵심 어투 패턴

```
① 공감 → 설명 패턴:
  "이것이 국소 최적화 함정(Local Optima) 입니다."
  "실생활에서도 이런 일은 흔합니다."

② 질문 → 답변 패턴:
  "왜 하필 11개일까요?" → (표로 설명)

③ 한 마디 정리 패턴:
  "한 마디로: 선형 회귀 = 직선 하나로 미래의 숫자를 예측하는 것!"

④ 비유 브릿지 패턴:
  기술 개념 → "마치 ~처럼" → 일상 사례
```

## 3. 비유 체계 (핵심 스타일 요소)

### 3.1 비유의 3가지 유형

이 책의 **가장 강력한 특징** 은 모든 기술 개념에 **일상 비유** 를 1:1 매칭하는 것입니다.

| 유형 | 설명 | 예시 |
|------|------|------|
| **일상생활 비유** | 누구나 아는 경험에 매칭 | 경사하강법 = "안개 속 산 내려오기" |
| **학교/공부 비유** | 학습자 공감대 활용 | 과적합 = "답을 외워서 시험 통과" |
| **직업/실무 비유** | 업무 경험 활용 | 학습 = "면허 학원", 추론 = "매일 출근 운전" |

### 3.2 비유 적용 공식

```
[기술 용어] = [한 줄 정의] + [비유] + [비유 확장]

예시:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
하이퍼파라미터 = "사람이 직접 정하는 설정값"

비유: 세탁기를 돌리는 것과 같습니다.
  → 수온: 30도? 60도? (= Learning Rate)
  → 세탁 시간: 30분? 60분? (= 에피소드 수)  
  → 탈수 강도: 약? 강? (= Epsilon Decay)
  → 한 번에 넣는 빨래 양: 3kg? (= 배치 사이즈)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 3.3 비유의 반복 심화

같은 비유를 챕터를 넘어 **반복·확장** 합니다.

```
1화: "시그모이드 → 확률 변환기" (처음 소개)
프롤로그: "이 시그모이드 함수, 기억해두세요. 1화에서 다시 등장합니다!" (복선)
1화: (실제 재등장) "프롤로그에서 봤던 시그모이드가 여기서 다시!" (회수)
```

## 5. 기술 설명 패턴

### 5.1 개념 도입 공식 (항상 반복)

```
Step 1: 스토리 맥락 ─── "팀장님이 ~라고 했습니다"
Step 2: 문제 직면   ─── "그런데 ~하면 어떻게 될까요?"
Step 3: 개념 소개   ─── "이것이 바로 [개념명](영어명) 입니다"
Step 4: 비유 설명   ─── "마치 ~와 같습니다"
Step 5: 코드 적용   ─── "코드로 보면 이렇습니다"
Step 6: 결과 확인   ─── "실행 결과: 성공률 X% → Y%!"
Step 7: 한 줄 요약  ─── "한 마디로: [개념] = [한 줄 설명]!"
```

### 5.2 코드 제시 방식

```python
# ❌ 하지 않는 것: 긴 코드 블록 + 라인별 주석
# ✅ 하는 것: 최소한의 핵심 코드만

# v1 (문제의 코드)
self.direction = 0  # 항상 위쪽만 보고 시작!

# v2 (해결된 코드)
self.direction = random.randint(0, 3)  
# 0: 위, 1: 오른쪽, 2: 아래, 3: 왼쪽
```

**코드 특징:**
- 전체 소스 나열 ❌ → **변경 부분만 before/after 비교** ✅
- 코드 뒤에 반드시 **자연어 해석** 추가
- 실행 명령어 안내: `cd simulator-v2 && python train.py`

### 5.3 용어 표기 규칙

```
첫 등장: 한국어명(영어명) — "과적합(Overfitting) 입니다"
재등장: 한국어명만 또는 영어만 — "과적합" 또는 "Overfitting"
약어: 풀네임 후 약어 — "Deep Q-Network(DQN)"
강조: 볼드 + 큰따옴표 — **"연습 문제는 완벽한데, 새 문제는 전혀 못 푸는 것"**
```

## 10. 프롬프트 활용 가이드 (에이전트 스타일 재현 시)

이 스타일로 글을 생성할 때 참고할 핵심 지침:

```
1. 반드시 주인공 캐릭터를 설정하라 (예: "메타코딩")
2. 매 챕터는 "실패 → 원인분석 → 해결 → 다음 도전" 구조로 작성하라
```
