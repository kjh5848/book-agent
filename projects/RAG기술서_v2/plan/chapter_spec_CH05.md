## 1. 챕터 섹션 구조

- 5.1 RAG 검색 품질을 결정하는 문서 기준: "쓰레기를 넣으면 쓰레기가 나온다(GIGO)." 문서 품질이 RAG 성능의 70%를 결정한다는 원칙. 어떤 문서를 선별해야 하는지 기준 제시.
- 5.2 PDF, Word, Markdown 수집 전략: 3,000페이지 중 핵심 50개 문서를 선별하는 전략. 파일 형식별 수집 방법. 디렉토리 구조 설계.
- 5.3 문서 전처리 및 정규화 가이드라인: 머리글/바닥글 제거, 표 정규화, 특수문자 처리. 일관된 Markdown 형식으로 변환하는 파이프라인.
- 5.4 문서 버전 관리 및 메타데이터 설계: 문서별 메타데이터(부서, 버전, 작성일, 카테고리). 버전 관리 전략. 메타데이터가 검색 품질에 미치는 영향.

## 3. 개념 설명 힌트 (Why)

- 문서 선별이 중요한 이유: 모든 문서를 넣으면 노이즈가 증가하여 검색 정확도가 떨어진다. 핵심 문서를 선별하는 것이 전체 문서를 넣는 것보다 성능이 좋다.
- 전처리가 필요한 이유: PDF의 머리글/바닥글, 페이지 번호 등이 검색 결과에 노이즈로 작용한다. 깨끗한 텍스트가 정확한 검색의 기본이다.
- 메타데이터가 중요한 이유: "HR 부서 문서에서만 검색"과 같은 필터링이 가능해지면 검색 정확도가 크게 향상된다.

## 4. 핵심 용어

- GIGO(Garbage In, Garbage Out): 입력 데이터 품질이 출력 품질을 결정한다는 원칙.
- 전처리(Preprocessing): 원시 데이터를 정제하여 사용 가능한 형태로 변환하는 과정.
- 정규화(Normalization): 다양한 형식의 문서를 일관된 형식으로 통일하는 과정.
- 메타데이터(Metadata): 문서에 대한 부가 정보 (부서, 버전, 작성일 등).

## 7. story_arc

이서연은 사내 매뉴얼 3,000페이지를 보고 절망한다. "이걸 다 어떻게 처리해요?" 김도현 팀장이 "전부 넣을 필요 없어. 핵심 문서 50개를 먼저 선별하자"고 방향을 잡아준다. 작은 것부터 시작하는 전략을 배운다. 이서연이 직접 문서를 분류하고 전처리하면서 "이 문서는 깨끗한데, 이건 표가 깨져 있네요"라며 데이터 품질의 중요성을 체감한다.
