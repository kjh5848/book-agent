### 항목 3: 볼딩 — 앞뒤 공백 규칙

- **현재 상태**: 아래 위치에서 볼드 앞뒤 공백 불일치가 확인됩니다.

  1. 원고 3번째 줄:
     ```
     이 장에서는 6장에서 구축한 ChromaDB 벡터 데이터베이스를 바탕으로 **RAG Q&A 엔진** 을 FastAPI 서비스로 완성합니다.
     ```
     여기서 `**RAG Q&A 엔진** 을` — 닫는 `**` 뒤와 조사 `을` 사이 공백 규칙은 준수되어 있으나, 앞의 `로 ` 뒤 공백이 없어 `**RAG Q&A 엔진**` 앞에 공백 없이 붙는 형태입니다. (렌더링 무방하나 스타일 가이드 기준 앞 공백 명시 필요)

  2. 7.1 섹션 본문:
     ```
     RAG Q&A 엔진을 구현할 때 웹 프레임워크로 **FastAPI** 를 선택합니다.
     ```
     `**FastAPI** 를` — 올바른 형식입니다.

  3. 7.6 정리하며 섹션의 다수 항목에서 볼드 뒤 바로 콜론(`:`)이 붙는 형태:
     ```
     - **FastAPI 서비스 계층화**: ...
     - **Jinja2 프롬프트 템플릿**: ...
     ```
     이는 정리 섹션 항목 앞 볼드의 경우 `**항목명**:` 형식으로 콜론이 바로 붙어 있습니다. 스타일 가이드는 볼드 뒤 공백을 명시하나, 마크다운 리스트 항목에서 `**제목**:` 패턴은 업계 관례상 허용 가능합니다. 다만 style.md 기준의 엄격 적용 시 `**제목** :` 형태가 요구됩니다.

- **기대 상태**: `style.md` 5항의 "볼드체(`**`) 사용 시 앞뒤 공백을 반드시 포함" 규칙에 따라, 정리하며 섹션의 리스트 항목 볼드 뒤에 공백 추가 또는 콜론을 별도로 처리해야 합니다.

- **수정 제안**:
  - 정리하며 항목들 `**항목명**: 설명` → `**항목명** : 설명` 또는 `**항목명**`: 형태로 통일합니다.
  - 단, 이 패턴은 챕터 구조 템플릿(`## 4. 정리하며` 예시)에서도 `- **핵심 1**: 설명` 형태를 제시하므로, 스킬 간 규칙 충돌이 있습니다. chapter-structure.md의 예시 형태를 우선 적용하면 현재 상태 PASS로 판단할 수 있습니다. **권장**: 스킬 규칙 명확화 전까지 chapter-structure.md 예시 형태(`**항목**: 설명`)를 유지하되, 경고로 기록합니다.
