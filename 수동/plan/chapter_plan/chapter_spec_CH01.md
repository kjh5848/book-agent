## 3. 시나리오 상세 (섹션 2 핵심)

집필 시 아래 시나리오를 단계별로 서술한다.
독자가 "아, 이런 흐름으로 동작하는구나"를 느끼도록 대화체 + 단계 번호 병행.

### 사용자 질문
> "김철수 씨의 남은 연차가 며칠이고, 연차 사용 기준은 어떻게 되나요?"

### 단계별 흐름

| 단계 | 동작 | 구성 요소 |
|------|------|---------|
| ① 질문 입력 | 사용자가 질문을 입력 | CLI / Web UI |
| ② 질문 라우팅 | "연차 잔여일" → 정형(DB), "연차 사용 기준" → 비정형(문서)으로 분류 | 질문 라우터 (LangChain) |
| ③-A MCP Tool 호출 | PostgreSQL에서 김철수의 잔여 연차 조회 → `5일` 반환 | MCP Tool + PostgreSQL |
| ③-B RAG Chain 호출 | "연차 사용 기준"으로 사내 규정 문서 벡터 검색 → 관련 문서 청크 3개 반환 | ChromaDB + 임베딩 모델 |
| ④ LLM 응답 합성 | DB 결과 + 문서 청크를 컨텍스트로 DeepSeek R1이 자연어 답변 생성 | Ollama (DeepSeek R1) |
| ⑤ 최종 답변 출력 | 출처 문서명 포함한 답변 반환 | FastAPI 응답 |

### 최종 답변 예시 (집필 시 박스로 표시)
```
김철수 씨의 남은 연차는 5일입니다.

연차 사용 기준 (사내 규정 v2.1, 3조 2항):
- 연차는 최소 1일 단위로 사용 가능합니다.
- 3일 이상 연속 사용 시 팀장 사전 승인이 필요합니다.
- 미사용 연차는 다음 해 3월 31일까지 이월됩니다.

[출처: HR_규정_2024.pdf, 3페이지]
```

## 4. 개념 설명 힌트 (Why)

- RAG를 선택하는 이유: Fine-tuning은 모델 재학습이 필요하지만, RAG는 기존 모델에 외부 지식을 실시간 주입 → 비용·복잡도 낮춤
- 로컬 LLM을 선택하는 이유: 사내 데이터 보안, API 비용 제거, 네트워크 독립성
- MCP를 도입하는 이유: 정형 데이터(DB)와 비정형 데이터(문서)를 하나의 에이전트에서 통합 질의

## 5. 핵심 용어

- RAG(Retrieval-Augmented Generation): 검색 증강 생성. 외부 문서를 검색하여 LLM 응답에 맥락을 제공하는 기법
- MCP(Model Context Protocol): LLM이 외부 도구(DB, API 등)를 호출할 수 있게 하는 프로토콜
- 환각(Hallucination): LLM이 사실이 아닌 내용을 그럴듯하게 생성하는 현상
- 벡터 DB(Vector Database): 텍스트를 숫자 벡터로 변환하여 유사도 기반 검색을 지원하는 데이터베이스
- 질문 라우터(Question Router): 질문 유형에 따라 MCP Tool과 RAG Chain 중 적절한 경로로 분기하는 컴포넌트

## 6. Mermaid 다이어그램 초안

```mermaid
flowchart TB
    U([\"사용자 질문\n'김철수 연차 + 연차 규정'\"])
    U --> R[\"질문 라우터\n(LangChain)\"]

    R -- \"정형: 잔여 연차\" --> M[\"MCP Tool\"]
    R -- \"비정형: 사용 기준\" --> V[\"RAG Chain\"]

    M --> PG[(\"PostgreSQL\n연차 DB\")]
    V --> CR[(\"ChromaDB\n사내 문서\")]

    PG -- \"5일\" --> S[\"LLM 응답 합성\n(DeepSeek R1)\"]
    CR -- \"규정 문서 청크\" --> S

    S --> A([\"최종 답변\n+ 출처 표시\"])
```
